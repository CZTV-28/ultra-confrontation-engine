# Ultra Confrontation Engine

Ultra Confrontation Engine is a Tauri desktop prototype built with React, TypeScript, Vite, and Rust. The app contains a battle simulator, replay viewer, settings page, and initial rule/content data for season S1.

## Tech Stack

- Frontend: React 19, TypeScript, Vite
- Desktop shell: Tauri 2
- State/i18n: Zustand, i18next
- Backend engine: Rust commands under `src-tauri/src`
- Game data: JSON files under `assets` and `src-tauri/assets`

## Project Layout

- `src/`: React app, pages, shared UI components, stores, styles
- `src-tauri/src/`: Rust battle engine, loaders, rules, models, and Tauri commands
- `assets/`: editable source game data
- `src-tauri/assets/`: runtime data used by the Tauri backend
- `replays/`: local replay files generated by the app

## Development

Install dependencies:

```powershell
npm install
```

Run the web frontend:

```powershell
npm run dev
```

Run the Tauri app:

```powershell
npm run tauri dev
```

Build the frontend:

```powershell
npm run build
```

Check the Rust backend:

```powershell
cd src-tauri
cargo check
```

## Current Migration Notes

- The migrated project builds successfully with `npm run build`.
- The Rust backend passes `cargo check` and has focused battle-engine unit tests under `src-tauri/src/battle.rs`.
- The previous template README has been replaced with project-specific notes.
- Generated folders such as `node_modules`, `dist`, and `src-tauri/target` should stay out of version control.
- Local `.ucr` replay files are treated as runtime output unless intentionally promoted to fixtures.
- The project is intended to be backed up through Git and a private GitHub repository.

## Known Issues

- There are duplicated game data files under `assets` and `src-tauri/assets`; decide which one is canonical and add a sync step if both must remain.
- No project-level test script is configured yet; run Rust tests with `cargo test` from `src-tauri`.
